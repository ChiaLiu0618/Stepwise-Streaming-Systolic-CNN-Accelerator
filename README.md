# Stepwise-Streaming Systolic CNN Accelerator

SystemVerilog CNN accelerator with four 9 × 8 systolic arrays, INT8
weights, and stepwise activation streaming. The compute path supports
convolution and fully connected layers, with accumulation, quantization,
ReLU, and max pooling.

![CNN accelerator architecture](docs/images/architecture.png)

The diagram shows the overall compute and memory flow. See the shared
weight storage section below for the current regfile organization.

## Project layout

```text
rtl/                 Accelerator, controller, PEs, buffers, and weight regfiles
tb/                 Testbenches
  unit/              Regfile, triangle buffer, and systolic array tests
  integration/       Accelerator functional test
  layers/            CONV1, CONV2, CONV3, and FC tests
data/               Input image and quantized weight text files
docs/               Weight storage organization and address mapping
run.sh              Simulation entry point
build/              Generated binaries, logs, and feature maps (ignored)
local/legacy/       Preserved local tool files and old outputs (ignored)
```

`local/legacy/` exists only in the original workspace; it is not needed to
run the source checkout. Technology libraries, tool projects, synthesis
reports, and waveforms are excluded from version control.

## Quick start

Install **Icarus Verilog** (`iverilog`, `vvp`) for the regfile test and
**Verilator**, **Make**, and a **C++20 compiler** for the other tests.
On macOS with Homebrew:

```sh
brew install icarus-verilog verilator
```

Run commands from the project root:

```sh
./run.sh                 # Accelerator functional test (default)
./run.sh regfiles        # Shared weight storage test
./run.sh triangle        # Triangle buffer test
./run.sh systolic        # Systolic array test
./run.sh functional      # Accelerator functional test
./run.sh network         # CONV1 → CONV2 → CONV3 → FC
./run.sh all             # Run the complete suite
./run.sh help            # Show available commands
```

The script resolves paths relative to its own location, so it also works
when invoked by absolute path from another directory. It exits nonzero
on compilation errors, simulation failures, or missing pass markers.

Build output and simulation logs are saved in `build/<target>/build.log`
and `build/<target>/run.log`; the Icarus regfile test has only a run log.
Network logs are in `build/network/<layer>/`. Each network run gets a fresh
`build/network/run.XXXXXX/` directory containing copied input data and the
feature maps generated by that run. Layers run in order so downstream tests
consume newly generated maps. The source data in `data/` is never overwritten.
The runner does not enable the optional vendor FSDB or gate-level hooks.

## Shared weight storage

Each group of four PEs at the same row and column across the four arrays
shares one **8-entry × 32-bit** regfile. There are 72 regfiles, totaling
**2,304 bytes**. Each entry contains four INT8 weights.

- Loading uses the existing five-bit page index: bits `[2:0]` select the
  entry and bits `[4:3]` select its byte lane.
- Convolution selects one of the 32 logical pages and broadcasts its byte
  to all four arrays.
- Fully connected compute uses indices 0–7 and sends one byte lane to each
  array, matching the original offsets of 0, 8, 16, and 24 pages.

Reads are combinational, writes are synchronous with byte enables, and
active-low asynchronous reset clears the storage. Weights stay resident
until overwritten or reset. See [weight regfile details](docs/weight_regfiles.txt).

## Validation

The suite includes a focused regfile test, block tests, an accelerator
functional test, and the ordered layer simulation flow. All eight testbenches
passed locally using Icarus Verilog and Verilator. The layer readers use
string buffers and portable hexadecimal scan formats; malformed rows stop
the simulation. Simulation checks
functional behavior; it does not establish post-synthesis timing or area.
